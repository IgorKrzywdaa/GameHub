
# Przypadki testowe – GameHub

## 1. Cel testowania

Celem testowania jest sprawdzenie poprawności działania i prezentacji elementów platformy GameHub oraz wykrywanie potencjalnych błędów.

## 2. Zakres testów

- Wyświetlanie strony głównej.
- Poprawność menu nawigacyjnego.
- Prezentacja informacji o grach.
- Wyświetlanie opisów i gatunków gier.
- Poprawność wyglądu strony na różnych urządzeniach.
- Czytelność i rozmieszczenie elementów interfejsu.

## 3. Scenariusze testowe

| ID | Nazwa testu | Oczekiwany rezultat |
|---|---|---|
| TC-01 | Wyświetlenie strony głównej | Strona ładuje się poprawnie |
| TC-02 | Wyświetlenie menu | Wszystkie elementy menu są widoczne |
| TC-03 | Wyświetlenie listy gier | Gry są prezentowane poprawnie |
| TC-04 | Wyświetlenie informacji o grze | Nazwa, opis i gatunek są czytelne |
| TC-05 | Sprawdzenie nawigacji | Odnośniki prowadzą do odpowiednich sekcji |
| TC-06 | Sprawdzenie responsywności | Układ dostosowuje się do rozdzielczości ekranu |
| TC-07 | Sprawdzenie wyglądu kart | Karty gier są poprawnie rozmieszczone |

## 4. Kryteria zaliczenia

Test uznaje się za zaliczony, jeżeli sprawdzany element działa zgodnie z oczekiwanym rezultatem.

W przypadku wykrycia błędu należy utworzyć odpowiednie zgłoszenie w GitHub Issues.

## 5. Raportowanie wyników

Wyniki testowania będą uzupełniane po otrzymaniu gotowych elementów od zespołu frontendowego i backendowego.
